# Self-Hosted Cloud Sync

[Cloud Sync](/cloud-sync) turns on once the worker has three values: a token, a
user id, and a hub URL. This page covers running that hub on a Cloudflare
account you control, on the Workers Free plan.

Auth is one shared token — no outbound token verification, no KV verdict
traffic. The hub's required projection endpoint is also a remote MCP endpoint
any MCP-aware agent can query.

```
machines (claude-mem worker) ──push/pull──▶ sync-hub-personal (Durable Object log)
                                                   │ projection (required)
                                                   ▼
                                            cmem-self-host (D1 + FTS5)
                                                   ▲
                    any MCP-aware agent ──── /u/<MCP_TOKEN>/mcp
```

The hub keeps the ordered operation log; the companion worker projects that
log into a D1 database with FTS5 search. The hub will not accept pushes unless
the projection checkpoint keeps up, so both workers are required.

<Info>
Source: `workers/sync-hub/` (hub) and `workers/self-host/` (projector + MCP).
Clone claude-mem and work from the repo root.
`workers/self-host/SELF-HOSTING.md` is the same runbook in-tree.
</Info>

## Before you start

- A Cloudflare account. The Free plan covers personal use.
- `wrangler` (`npm i -g wrangler`) and `bun`.
- Both `wrangler.jsonc` templates ship with placeholder resource ids — copy
  each to a gitignored `*.local.jsonc` and put your real ids there, out of git
  history.

<Warning>
**Privacy:** cloud sync uploads your observation narratives and full prompt
text. Self-hosting moves that data to infrastructure you own; it does not
reduce what gets uploaded.
</Warning>

## 1. Mint the credentials

Four values, once. Keep them in your password manager.

```sh
uuidgen | tr 'A-Z' 'a-z'      # SYNC_STATIC_USER_ID — names your hub log
openssl rand -hex 32          # SYNC_STATIC_TOKEN — sync credential, shared by your machines
openssl rand -hex 32          # CMEM_INTERNAL_PROJECTOR_SECRET — hub ⇄ projector, also the admin-API credential
openssl rand -hex 32          # MCP_TOKEN — remote MCP credential
```

## 2. Deploy the companion worker

Deploy this one first: the hub reaches it through a service binding, which
fails to deploy if the target worker does not exist yet.

```sh
cd workers/self-host
cp wrangler.jsonc wrangler.local.jsonc   # gitignored copy holds your real ids
wrangler d1 create cmem-memory           # paste the id into wrangler.local.jsonc
wrangler secret put CMEM_INTERNAL_PROJECTOR_SECRET -c wrangler.local.jsonc
wrangler secret put MCP_TOKEN                      -c wrangler.local.jsonc
wrangler deploy -c wrangler.local.jsonc  # → https://cmem-self-host.<SUBDOMAIN>.workers.dev
```

The worker applies its D1 schema lazily and idempotently on first use. There is
no `wrangler d1 execute` step.

## 3. Deploy the hub

```sh
cd workers/sync-hub
wrangler kv namespace create sync-hub-personal-AUTH_CACHE
cp wrangler.personal.jsonc wrangler.personal.local.jsonc
```

Fill in the three `REPLACE_WITH_*` values in the copy — the KV namespace id,
your `SYNC_STATIC_USER_ID`, and your `cmem-self-host` subdomain in
`INTERNAL_PROJECTOR_URL` — then deploy:

```sh
wrangler secret put SYNC_STATIC_TOKEN              -c wrangler.personal.local.jsonc
wrangler secret put CMEM_INTERNAL_PROJECTOR_SECRET -c wrangler.personal.local.jsonc  # same value as step 2
wrangler deploy -c wrangler.personal.local.jsonc   # → https://sync-hub-personal.<SUBDOMAIN>.workers.dev
```

Differences from the multi-user hub config in `wrangler.jsonc`:
`AUTH_MODE=static` replaces the token verify endpoint, cron triggers are gone
(the watchdog and control-plane probe are fleet-ops tooling), and
`INTERNAL_PROJECTOR_URL` points at your companion worker.

Confirm the hub can reach its projector:

```sh
curl -s https://sync-hub-personal.<SUBDOMAIN>.workers.dev/v1/sync/status \
  -H "Authorization: Bearer $SYNC_STATIC_TOKEN" \
  -H "X-User-Id: $SYNC_STATIC_USER_ID" -H "X-Device-Id: smoke"
```

## 4. Smoke test with the canary

Run this before your real corpus is live. The canary writes real ops into the
log, so reset afterwards.

```sh
bun workers/sync-hub/canary/canary.ts \
  --hub https://sync-hub-personal.<SUBDOMAIN>.workers.dev \
  --user $SYNC_STATIC_USER_ID --token $SYNC_STATIC_TOKEN --cycles 3 --interval-ms 1000
```

Expect `"converged":true`. Then wipe what the canary wrote:

```sh
curl -s -X POST https://sync-hub-personal.<SUBDOMAIN>.workers.dev/internal/v1/sync/reset \
  -H "Authorization: Bearer $CMEM_INTERNAL_PROJECTOR_SECRET" \
  -H "Content-Type: application/json" \
  -d "{\"protocol_version\":1,\"user_id\":\"$SYNC_STATIC_USER_ID\"}"
```

Reset clears the hub log only. D1 rows are guarded by `entity_rev`, so if the
canary data reached the projector, clear it too:

```sh
wrangler d1 execute cmem-memory --remote \
  --command "DELETE FROM observations; DELETE FROM entities;"
```

## 5. Configure each machine

Run the `/cloud-sync` skill and paste the values, or merge them into
`~/.claude-mem/settings.json` by hand (mode `0600`):

| Setting | Value |
|---|---|
| `CLAUDE_MEM_CLOUD_SYNC_TOKEN` | your `SYNC_STATIC_TOKEN` |
| `CLAUDE_MEM_CLOUD_SYNC_USER_ID` | your `SYNC_STATIC_USER_ID` uuid |
| `CLAUDE_MEM_CLOUD_SYNC_HUB_URL` | `https://sync-hub-personal.<SUBDOMAIN>.workers.dev` |

Leave `CLAUDE_MEM_CLOUD_SYNC_DEVICE_ID` empty — the worker mints one per
machine. Restart the worker and confirm:

```sh
# the worker's port: CLAUDE_MEM_WORKER_PORT, else the value in
# ~/.claude-mem/settings.json, else the per-uid default 37700 + (uid % 100)
PORT="${CLAUDE_MEM_WORKER_PORT:-$(node -e "const fs=require('fs'),p=require('path'),os=require('os');const uid=(typeof process.getuid==='function'?process.getuid():77);const fb=String(37700+(uid%100));try{const s=JSON.parse(fs.readFileSync(p.join(os.homedir(),'.claude-mem','settings.json'),'utf-8'));const e=s.env&&typeof s.env==='object'?s.env:s;process.stdout.write(String(e.CLAUDE_MEM_WORKER_PORT||s.CLAUDE_MEM_WORKER_PORT||fb));}catch{process.stdout.write(fb);}" 2>/dev/null)}"

curl -s -X POST http://127.0.0.1:$PORT/api/admin/restart
curl -s http://127.0.0.1:$PORT/api/sync/status   # configured:true, hub.reachable:true
```

Full settings table and status fields: [Cloud Sync](/cloud-sync).

### Live updates

claude-mem 13.37+ asks the hub for a live channel (`POST /v1/sync/realtime-token`,
then a WebSocket on `/v1/sync/realtime`). The hub signs that channel's
credentials with `CMEM_INTERNAL_PROJECTOR_SECRET`, so it needs no extra setup:
a write on one machine reaches the others in about a second instead of on the
next 30-second (active) or 5-minute (idle) poll. Each open channel wakes the
hub's Durable Object for one heartbeat every 25 seconds, well inside the Free
plan's request allowance. A worker that saw a hub without the live channel
re-checks only once an hour; restart it after upgrading the hub.

## 6. Point MCP consumers at your memory

```sh
claude mcp add --transport http cmem \
  https://cmem-self-host.<SUBDOMAIN>.workers.dev/mcp \
  --header "Authorization: Bearer $MCP_TOKEN"
```

Agents that cannot set headers use the path form:
`https://cmem-self-host.<SUBDOMAIN>.workers.dev/u/$MCP_TOKEN/mcp`.

Tools: `search`, `timeline`, `get_observations`, `recent_memories`,
`important_workflow` — the same index-first workflow as the local MCP server.

## 7. Backfill pre-launch history (optional)

Sync skips rows written before the launch baseline. To upload them, stop the
worker and run this **once, on one machine** — the one with the fullest
history:

```sh
bun scripts/self-host-backfill.ts
```

<Warning>
Backfilling from a second machine uploads the overlapping history as distinct
entities and duplicates it on every device.
</Warning>

A large backfill can span the Free plan's daily caps. The client's backoff
resumes it without losing rows.

## Operating notes

- **Rotating the sync token:** `wrangler secret put SYNC_STATIC_TOKEN -c
  wrangler.personal.local.jsonc`, then update the settings file on each
  machine. No cache to wait out — static mode never touches KV.
- **Free-plan caps** (reset at midnight UTC) cost you latency, not data.
  Unsynced rows stay queued locally and the drain retries.
- **The projector is on the push path.** If `cmem-self-host` errors, the hub
  returns 503 and the client retries; the data is safe in the hub log. After an
  outage, `POST /internal/v1/projection/drain` on the hub (projector secret)
  catches the checkpoint back up.
- **Device ceiling:** 64 distinct device ids per user id.
